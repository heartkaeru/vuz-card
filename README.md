# ВУЗ-CRM: Интеллектуальный ассистент по работе с ВУЗ/СПО

Интеллектуальная CRM-система со встроенным ИИ-агентом для автоматизации сбора данных о вузах и колледжах, выявления возможностей для партнёрства и быстрой подготовки к встречам с руководством учебных заведений.

---

## 📌 Проблематика

Сотрудники профильных подразделений (Учебный центр, Блоки ЛиК, РКиСП, РГС) регулярно проводят встречи с ректоратом и топ-менеджментом ВУЗ/СПО. 
Текущий процесс подготовки сопряжён с рядом трудностей:
* **Ручной поиск информации:** сведения о руководстве, проектах и мероприятиях разыскиваются в интернете вручную под каждую встречу.
* **Разрозненность контактов:** база ключевых лиц ведётся в таблицах Excel без единого стандарта и версионирования.
* **Сложность мониторинга:** кадровые перестановки и новые инициативы вузов часто отслеживаются с опозданием.
* **Высокие трудозатраты на презентации:** на ручную сборку отчётов и слайдов для переговоров уходит значительное время экспертов.

---

## 🎯 Цель проекта

Создать CRM-систему со встроенным **ИИ-агентом**, который:
1. Автоматически находит и агрегирует информацию о ВУЗе/СПО из открытых источников в единую интерактивную **«Карточку ВУЗа»**.
2. Отслеживает актуальность данных (руководство, контакты, новости, ключевые события).
3. Анализирует синергию и сопоставляет инициативы вуза с образовательными программами и партнёрскими предложениями Сбера.
4. В один клик формирует готовую презентацию (.pptx) и аналитическую справку к встрече с руководством учебного заведения.

---

## 🚀 Функциональность (1-й этап / MVP)

### 1. Сбор сведений о ВУЗе/СПО (ИИ-парсер)
* **Руководство:** ФИО ректора и проректоров, их должности, зоны ответственности и биографические справки.
* **Контакты:** телефоны, корпоративная почта ключевых сотрудников и подразделений.
* **Проекты ВУЗа:** участие в федеральных программах («Приоритет-2030», «Передовые инженерные школы» и др.), региональные и научно-исследовательские проекты (НИОКР, гранты).
* **События и жизнь кампуса:** студенческие, научные и образовательные мероприятия, карьерные форумы.

### 2. Контроль актуальности данных
* Отслеживание кадровых изменений в руководстве.
* Мониторинг новостной повестки и анонсов мероприятий для заблаговременного подключения команды к событиям вуза.

### 3. Выявление возможностей для сотрудничества
* Автоматический матчинг профиля и потребностей вуза с линейкой образовательных продуктов Сбера (Школа 21, Edutoria, СберОбразование, акселераторы SberStudent/SberZ, цифровые кафедры, стажировки).
* Поиск пересечений с успешными кейсами и инициативами в других регионах.

### 4. Подготовка материалов к встрече
* Единая структурированная карточка ВУЗа с возможностью ручной верификации и корректировки данных сотрудником (*Human-in-the-loop*).
* Экспорт брендированной презентации к встрече в формате PowerPoint (`.pptx`).

## 🏗️ Архитектура системы

* **CRM-платформа (Open-Source CRM):** ведение реестра ВУЗов, кастомная сущность «Карточка ВУЗа», управление пользователями, правами доступа и историей изменений.
* **Сервис ИИ-агента (Python-микросервис):**
  * *Поисково-парсинговый блок:* сбор информации с сайтов учебных заведений и новостных агрегаторов.
  * *LLM-экстрактор:* выделение сущностей, структурирование биографий руководства, контактов и проектов.
  * *Матчер партнёрств:* анализ пересечений с матрицей предложений Сбера.
  * *API-коннектор к CRM:* передача собранных данных в CRM для верификации пользователем.
* **Модуль формирования документов:** двухэтапная сборка презентаций:
  1. *LLM-сценарист:* генерация структуры слайдов, тезисов и подбор аргументов под специфику ВУЗа;
  2. *Шаблонизатор (.pptx):* программная сборка файлов строго по корпоративному дизайн-шаблону Сбера (`python-pptx`).

## 🛠️ Стек технологий (предварительный)

* **CRM-платформа:** Open-Source CRM (рассматриваются варианты: **EspoCRM**, **SuiteCRM**, **Odoo Community** и др. — финальный выбор уточняется по результатам тестирования API и гибкости настройки карточек)
* **Сервис ИИ-агента:** Python 3.11+ (FastAPI / Celery или фоновый worker-сервис)
* **Ядро ИИ (LLM):** 
  * Приоритет — **GigaChat API** (GigaChat Pro/Max) как целевое корпоративное решение Сбера;
  * Архитектура строится **провайдеро-независимой** (через абстрактный интерфейс/адаптеры), что позволяет подключать другие модели (включая open-source или специализированные мультимодальные модели для OCR/анализа PDF-сканов) при необходимости.
* **Сбор данных:** BeautifulSoup4, Playwright / httpx, веб-поисковые коннекторы
* **Генерация презентаций:** `python-pptx` + корпоративный шаблон презентаций
* **База данных / Хранилище:** зависит от выбранной CRM (MySQL / PostgreSQL / MariaDB)
