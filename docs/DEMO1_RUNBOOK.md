# Демо 1 — запуск и сценарий защиты 7 ноября 2026

Приоритет, уточнённый по сообщению куратора: работающий интерфейс CRM, поиск/
актуализация сведений о должностных лицах и формирование презентации по шаблону.
Матчинг продуктов, проекты/события и полноценный свободный диалог не блокируют Демо 1.
Полный состав MVP в README остаётся более широким планом проекта.

## Обычный запуск — реальные сайты и GigaChat

Два терминала из корня репозитория:

```powershell
Set-Location backend
.venv/Scripts/python.exe run.py
```

```powershell
Set-Location frontend
pnpm install --frozen-lockfile
pnpm dev
```

Открыть [интерфейс](http://127.0.0.1:3000); API — [Swagger](http://127.0.0.1:8000/docs).
Backend запускается только на `127.0.0.1`. `run.py` явно загружает `backend/.env`;
ключ, модель, scope и доверенный сертификат настраиваются по `backend/LLM_README.md`.
Участники после клонирования устанавливают backend-зависимости в своё окружение:
`python -m pip install -r requirements-dev.txt` из `backend`.

Для просмотра уже сохранённого контрольного сбора БГУ в текущем рабочем окружении:

```powershell
Set-Location backend
.venv/Scripts/python.exe run.py --db output/demo1-live-bgu/registry.sqlite3
```

Это альтернативный запуск, не второй сервер на том же порту. База в `output` локальная,
не входит в Git. Без этого файла другой участник начинает с обычного запуска/новой карточки.

## Сценарий в интерфейсе

1. Найти учреждение в списке или создать черновик с названием, городом и официальным
   сайтом. Черновик не создаёт фиктивный ИНН или подтверждённое юридическое лицо.
2. Открыть карточку. При необходимости указать точную страницу руководства внутри
   раскрываемого блока. Например, для БГУ: `https://bgu.ru/sveden/managers/`, сайт `https://bgu.ru/`.
3. Нажать «Найти и обновить руководство». Дождаться статуса; парсер посещает живой
   источник, LLM обрабатывает тексты. Недоступный сайт/ошибка модели не подменяются примером.
4. Во вкладке руководства раскрыть источники и цитаты. Выбрать корректные факты,
   указать проверяющего, основание и подтвердить проверку действующих первоисточников.
   Кнопка выбора всех выбирает только `pending` без ошибок; это не автоматическое принятие.
5. Принять или отклонить выбранное. Конфликты и ошибки нельзя обойти галочкой проверки:
   их нужно уточнить/исправить в источниках или получить корректный новый сбор.
6. Указать цель и необязательную дату встречи, затем сформировать презентацию.
   Контекст сохраняется с материалом и используется в справке/слайдах; он не становится
   фактом об учреждении. Генерация читает только принятые свежие факты из БД,
   а не произвольный JSON браузера. После фактической сборки появятся ссылки на PPTX/справку.
7. Скачать PPTX, открыть его, проверить текст и источники. Файл остаётся черновиком.
   В разделе «Отчёты» показываются реально созданные файлы; после изменения фактов
   старая версия отмечается архивной и не выдаётся как актуальная.

Чат умеет запускать те же два действия командами «Обновить данные» и «Сформировать
презентацию». Это ограниченный помощник над выбранной карточкой, не универсальный
поисковик/свободный диалог. Поиск в списке ищет по каталогу/сохранённым карточкам;
для произвольного учреждения нужен официальный URL. Без сайта организация не угадывается.

В блоке качества сбора показаны причины отклонения кандидатов, ограничения обработки
и пропуски модели. Пропуск не доказывает отсутствие сведений на сайте. Контакты с
неподтверждённым владельцем по-прежнему нельзя принять.

## Проверка актуализации

В разделе «Руководство и контакты» после повторного сбора доступны:

- «Подтверждённая карточка» с ранее принятыми сведениями и датами их проверки;
- сравнение «Было принято / Получено в новом сборе» с цитатами и ссылками с обеих сторон;
- новые и изменённые поля, возможная смена руководителя, сведения без изменений
  и сведения, не подтверждённые повторным сбором;
- история последних 20 сборов: предыдущие версии доступны только для просмотра.

Для замены выберите новые сведения, проверьте старый и новый первоисточники,
укажите проверяющего и основание, подтвердите проверку источников и отдельное
согласие на архивирование прежних значений. Без этого замена заблокирована.
Отклонённый кандидат не заменяет старый факт. Возможная смена руководителя
требует отдельного подтверждения архивирования его прежнего профиля:
старые телефон и биография не переносятся новому человеку.

Пропуск или ошибка сбора не удаляет принятые данные и не обновляет дату их проверки.
Материалы можно сформировать по сохранившимся принятым фактам, если они проходят
действующие проверки актуальности. После неудачного извлечения в справке будет
предупреждение об использовании прежних сведений. Мониторинг по расписанию ещё не реализован.

Воспроизводимая репетиция с изменением вымышленного телефона (вместо обычного backend):

```powershell
Set-Location backend
.venv/Scripts/python.exe -m examples.llm.actualization_demo
```

В списке выберите «Учебный пример обновления (вымышленные данные)» → «Проверить факты».
Отдельная база: `backend/output/actualization-offline/registry.sqlite3`.
Исходные решения помечены как синтетические; реальные сведения, GigaChat и сеть
в этой репетиции не используются. Для обычной работы остановите учебный сервер
и запустите `run.py` со своей рабочей базой.

## Презентация

Перед генерацией выберите вариант: «Краткая карточка — 3 слайда» для встречи
или «Подробная справка — все разделы» для подготовки. Предпросмотр использует
тот же выбор. Краткая версия содержит руководителя, сведения об учреждении и
повестку; полные значения и цитаты доступны в текстовой справке и заметках PPTX.
Изменение варианта не принимает новые факты и не обновляет даты их проверки.

Основной [шаблон](../backend/templates/README.md) адаптирован по примерам заказчика:
карточка учреждения, руководство/контакты, биография/ответственность, вопросы,
контекстные тезисы при наличии и источники. Секции без принятых данных не заполняются
старыми показателями/фото из примера. Структура отдельно в `customer-card.json`;
после согласования её можно менять без переписывания извлечения фактов.

## Учебная репетиция без сети/API — отдельный режим

Вместо обычного backend запустить:

```powershell
Set-Location backend
.venv/Scripts/python.exe -m examples.llm.demo1_server
```

Frontend запускается так же. Использовать карточку с явно учебным названием и URL
`https://university.example`. Здесь фиктивный HTML и сохранённые ответы, GigaChat и
живой обход не выполняются. В интерфейсе и PPTX есть отметка учебного режима.
База отдельная: `backend/output/demo1-offline/registry.sqlite3`.
Ручное принятие в этой репетиции не подтверждает сведения о реальном вузе.
Обычный сервер никогда автоматически не переключается на этот режим при ошибке.

## Что нужно сделать команде до защиты

- **Данил + Дарья:** совместно повторить путь от UI до файла в обычном режиме,
  проверить выбранные факты и итоговый текст. Адаптер уже подключён через `/api/v1/ai`.
- **Артём:** выбрать 2–3 стабильные официальные страницы, проверить границы филиалов
  и владельцев контактов. В контрольном БГУ ФИО/должности прошли, часть контактов отвергнута.
- **Максим:** проверить дополнительные `llm_*` таблицы для исследований/решений/материалов.
  Основная схема реестра и `PRAGMA user_version=1` не менялись. Excel-кандидаты ещё
  не превращаются автоматически в карточки интерфейса; подтверждённые ID доступны общему сервису.
- **Ангелина:** проверить новый блок руководства, формы, ошибки и скачивание на экране защиты.

Локальный прототип ещё не реализует вход/роли: имя проверяющего вводится вручную.
Для общего развёртывания backend должен брать автора из аутентифицированной учётной
записи и добавить очередь worker; текущие задания выполняются в одном процессе FastAPI.
При перезапуске незавершённые задания помечаются ошибочными для явного повтора.
