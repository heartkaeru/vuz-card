# Диалог с агентом и материалы по новому учреждению

Статус: предложение для команды и заказчика. Сценарий уточняет продуктовые требования;
чат, поиск нового учреждения и создание карточки по запросу пока не реализованы.
Реализованный LLM-модуль работает с переданными текстами и фрагментами.
Также реализован отдельный [разбор первого запроса](../../backend/docs/llm/LLM_REQUESTS.md):
он возвращает структуру задания и необходимые уточнения, без поиска и записи в CRM.

## Пользовательский сценарий

Авторизованный сотрудник пишет, например:

> Подготовь справку и презентацию о педагогическом колледже в городе N
> к встрече с директором. Его ещё нет в нашей базе. Вот официальный сайт: …

Агент принимает название, город/регион, официальный URL при наличии, цель встречи,
дату и желаемый шаблон. Наличие карточки заранее не является обязательным условием.
Необязательные цель/дата могут остаться неизвестными; агент не придумывает их.

1. **Определить задачу.** Преобразовать сообщение в структурированный запрос:
   найти учреждение, подготовить справку, презентацию либо оба результата.
2. **Найти организацию.** Проверить доступные пользователю карточки, варианты названия,
   город, официальный сайт и принадлежность филиала/колледжа. Совпадение аббревиатуры
   не означает совпадение организации. Уже существующая карточка должна использоваться
   повторно, если личность организации подтверждена.
3. **Уточнить неоднозначность.** Если название соответствует нескольким учреждениям,
   показать варианты с городом и сайтом, попросить выбрать. При отсутствии надёжного
   кандидата попросить название/город/официальный URL. Не создавать карточку догадкой.
4. **Начать первичный сбор.** Если карточки нет, сервер создаёт задание первичного
   исследования и черновую запись после определения организации. Поиск находит
   первоисточники, парсер получает тексты/фрагменты, LLM извлекает кандидатов фактов.
   Внешняя поисковая выдача сама по себе не подтверждает факты.
5. **Показать результат проверки.** Агент сообщает, какие сведения найдены, даёт
   источники, показывает пропуски и конфликты. Новые факты ожидают принятия сотрудником;
   они не становятся `verified` в результате сообщения «создай презентацию».
6. **Собрать материалы.** После принятия фактов генератор готовит справку и тезисы,
   а модуль документов собирает `.pptx` по выбранному шаблону. Ссылки на факты, источники,
   версию карточки и версию шаблона сохраняются. По существующей проверенной карточке
   этот этап возможен сразу, если не требуется актуализация.
7. **Продолжить диалог.** Пользователь может попросить сократить биографию, изменить
   цель встречи, оставить выбранные разделы либо повторить сбор. Редакционная правка
   не добавляет новые факты; запрос новых сведений запускает сбор и проверку.

Короткий пример ожидаемого диалога, не демонстрация работающего чата:

> Пользователь: Сделай презентацию о колледже X в городе N.
>
> Агент: Карточки ещё нет. Нашёл официальный сайт учреждения X в городе N.
> Начал сбор руководства, контактов и доступных проектов.
>
> Агент: Собран черновик карточки. Показываю источники и факты для проверки.
> Для двух показателей данных не найдено; они будут обозначены как пробелы.
>
> Пользователь принимает выбранные факты в интерфейсе проверки.
>
> Агент: Справка и презентация сформированы по принятой версии карточки.
> Файлы доступны по ссылкам.

Последнее сообщение допускается только после действительного создания файлов.
Если требуется выбор организации или принятие фактов, агент явно сообщает об этом,
а не оставляет пользователя ждать фонового «успешного» задания.

## Состояния процесса

| Состояние | Что видит пользователь | Следующее действие |
|---|---|---|
| Нужно уточнение | Вопрос и кандидаты организаций | Выбор/дополнение пользователем |
| Поиск источников | Начат сбор, ссылка на задание | Фоновый поиск и загрузка |
| Извлечение | Материалы получены, идёт обработка | Проверка кандидатов и источников |
| Нужна проверка фактов | Карточка с источниками, пропусками и конфликтами | Принятие уполномоченным сотрудником |
| Генерация материалов | Выбраны факты и шаблон, идёт сборка | Генератор и шаблонизатор |
| Готово | Реальные ссылки на справку/файл | Просмотр, скачивание или правки |
| Частичный результат | Что получено, что недоступно и почему | Продолжение по доступным данным или повтор |
| Ошибка | Понятная причина и возможность повтора | Повтор/уточнение без скрытого создания дубля |

Если источники недоступны или данных недостаточно, агент не утверждает, что учреждение
не существует или у него нет проектов. Пустое поле не заполняется знаниями модели.
Отсутствие внутренних данных о сотрудничестве со Сбером не препятствует публичной
справке, но не даёт оснований выдумывать договоры, встречи или партнёрства.

## Разделение компонентов

| Компонент | Ответственность |
|---|---|
| Диалоговый интерфейс | Сообщение, уточнения, выбор учреждения, прогресс, просмотр источников и файлов |
| Интерпретатор запроса | Намерение, название/URL/город, цель встречи, формат результата; без записи в БД |
| Сервер-координатор | Права, поиск дублей, контекст диалога, черновик организации, задания, статусы и версии |
| Поиск и парсер | Официальные источники, загрузка, снимки, фрагменты и области владельцев контактов |
| LLM-экстрактор | Кандидаты фактов по переданным источникам; без самостоятельного утверждения |
| Проверка сотрудником | Принятие/отклонение и разрешение конфликтов с журналом решения |
| Генератор и модуль документов | Текст по принятым фактам и реальный `.pptx` по шаблону |

Чат и действия на экране карточки должны использовать один серверный процесс.
Нельзя реализовать два независимых способа обновления данных с разными правилами проверки.
Само название «ИИ-агент» не означает, что выбранная LLM автоматически имеет поиск,
доступ к CRM, память диалога или возможность создавать файлы: эти инструменты подключает сервер.

## Учреждение ещё не имеет ID

Сервер сначала присваивает `request_id` исследованию. После разрешения личности
организации он выдаёт внутренний ID черновой карточки и версию 1. Этот ID подходит
для текущего `Institution.id` в контракте извлечения. Отсутствующий ИНН не заменяется
фиктивным значением; черновик не считается проверенной записью юридического лица.
Если при сохранении обнаружен дубль, исследование связывается с существующей карточкой
после проверки личности и прав, без переноса фактов к похожему учреждению наугад.

При повторном сообщении/доставке задания сервер повторно использует исследование
по ключу запроса и не создаёт несколько карточек или применений одних данных.
Генерация фиксирует версию принятой карточки; более поздние изменения её не перезаписывает.

## Предложение по объёму разработки

Первый диалоговый сценарий: запрос «подготовить материалы», уточнение учреждения,
состояние задания, переход к проверке и получение результата. Произвольные команды
изменения CRM и полноценная история любых переговоров не становятся автоматически
частью первого прототипа. Конкретный вид экрана чата согласуется с командой и заказчиком.

Нужны серверные операции разрешения организации и первичного исследования без
заранее существующего `university_id`. Их точные адреса и модели согласует backend.
Существующего `POST /universities/{id}/refresh` для этого недостаточно.

## Приёмочные сценарии

1. Известный вуз и актуальные принятые факты: запрос приводит к сборке материалов.
2. Новый вуз с официальным URL: создано первичное исследование и черновик без фиктивных реквизитов.
3. Одинаковая аббревиатура в разных городах: агент уточняет учреждение до применения данных.
4. Колледж/филиал при вузе: сведения не переносятся в карточку головной организации автоматически.
5. Источники недоступны: показана ошибка/частичный результат, факты не выдуманы.
6. Обнаружены новые сведения: пользователь получает очередь проверки, а не автоматически принятые факты.
7. Повтор запроса не создаёт дубль карточки; ответ «готово» содержит только действительно созданные файлы.
8. Просьба изменить стиль текста не меняет факты и их источники.

Этот сценарий не зависит от конкретной CRM или поискового провайдера. До реализации
сервера/парсера LLM-модуль продолжает проверяться на сохранённых публичных источниках.
