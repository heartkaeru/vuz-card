# Цели и гипотезы тестирования

Документ для презентации: что проверяли, какие гипотезы выдвигали, по каким критериям
считали успех и что получилось в пилоте. Фактические замеры и формулы — в
[`METRICS.md`](METRICS.md), сырые данные — в [`pilot_measurements.csv`](pilot_measurements.csv).

---

## 1. Цель тестирования

Проверить, что карточка вуза собирается автоматически и её данных достаточно для работы
без ручного сбора: сайт, ректор, руководство, контакты — за минуты, а не часы.

## 2. Задачи тестирования

1. Убедиться, что официальный сайт и ректор определяются без ручных ссылок.
2. Оценить полноту руководства и контактов.
3. Оценить достоверность данных: сколько кандидатов отсеивает автопроверка.
4. Замерить скорость сбора.
5. Проверить устойчивость на вузах с разной вёрсткой сайтов.

## 3. Гипотезы и критерии успеха

| № | Гипотеза | Метрика | Критерий успеха | Факт пилота |
|---|---|---|---|---|
| H1 | Сайт и ректор находятся автоматически, ручная ссылка не нужна | доля вузов с найденным сайтом / ректором | сайт ≥ 95 %, ректор ≥ 98 % | **10/10 и 10/10** |
| H2 | Собранных данных достаточно для работы отдела | медиана записей руководства и контактов | ≥ 50 и ≥ 50 | **248 и 199** |
| H3 | Данным можно доверять без ручной сверки каждого факта | доля отклонённых автопроверкой; доля корректных ФИО и должностей | отклонено ≤ 15 %; корректных ≥ 98 % | **10,4 %** (17 из 163); **100 %** (0 склеенных должностей на 2089 записей) |
| H4 | Скорость приемлема для рабочего сценария | время карточки; p95 парсинга | ≤ 10 мин; ≤ 300 с | **3,5 мин** (медиана); **263 с** |
| H5 | Решение устойчиво к разным сайтам, а не к одному «удобному» | доля сборов без ошибок парсера | ≥ 95 % | **10/10** |

## 4. Формулировка для слайда

> **Гипотеза:** автоматический сбор заменит ручной.
> **Критерий:** 95 % вузов без ручных ссылок, ≥ 50 записей руководства, ≤ 15 % отклонённых,
> ≤ 10 минут на карточку.
> **Результат:** 10 из 10, 248 записей, 10,4 %, 3,5 минуты.

## 5. Как проверяли

- Выборка: 10 вузов разного типа — МГУ, УрФУ, ЮУрГУ, КФУ, СПбГУ, НИУ ВШЭ, МФТИ, РУДН,
  НГУ, МГТУ им. Баумана.
- Один сценарий для всех: создание карточки по названию → сбор → извлечение фактов.
- Источники цифр: `created_at`/`completed_at` задач, `card.leadership`, `card.contacts`,
  `card.errors`, `facts[].verification_status`.
- Отклонение кандидата = факт со статусом `rejected` после автопроверки доказательств.
- Корректная должность = без склейки строк и без «хвоста» абзаца.

## 6. Что в эту итерацию не входило

- Заполнение профиля «О вузе» (город, дата основания, студенты) — 0 из 8 полей, в работе.
- Отображение фото ректора в интерфейсе — парсер фото находит (8/10), UI пока не выводит.
- Репрезентативность: 10 вузов, не все ~1200 вузов РФ.
