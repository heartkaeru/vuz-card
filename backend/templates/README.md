# Шаблоны презентации

## Два варианта

В интерфейсе можно выбрать «Краткая карточка» (`compact`) или
«Подробная справка — все разделы» (`detailed`). Выбор применяется также к
предпросмотру кандидатов. По умолчанию интерфейс предлагает краткую карточку;
старые вызовы API и сохранённые материалы без этого поля остаются подробными.

`customer-compact.json` / `customer-compact-v1` задаёт компактное оформление по
структуре примеров заказчика, с теми же фирменными изображениями. Базовые слайды
без отдельной обложки: руководитель, справочная информация об учреждении и
повестка встречи. При переданных результатах матчинга добавляется слайд
«Предложения и партнерство со Сбером» (по одному слайду на каждое предложение).
Если URL официального фото ректора передан при генерации, портрет скачивается
с домена его принятых источников и размещается на слайде руководителя.

На слайдах выводятся ключевые факты в пределах читаемого объёма. Для длинной
записи об учёной степени/звании допускается выбрать явно указанную в ней
буквальную формулировку квалификации. Карьерная история ограничена двумя
последними датированными выдержками; дата из биографии не становится текущей
должностью. Слишком длинные значения не обрезаются молча: полные записи,
остальные факты, цитаты и ссылки сохраняются в заметках и текстовой справке.
Численность выводится только целиком с периодом, составом, охватом и единицей;
при нехватке места она остаётся в полной справке, без отдельного числа на слайде.

Проекты и мероприятия выводятся с их опубликованным статусом, ролью и датами
при наличии. Без подтверждённых проектов ставится явная отметка; общие вопросы
для обсуждения не выдаются за факты. Ссылки на слайдах кликабельны, полные URL
и страницы PDF остаются в заметках. В учебном режиме и предпросмотре сохраняются
обязательные отметки; краткий формат не принимает факты автоматически.

API генерации принимает `presentation_variant: "compact" | "detailed"`,
необязательный `rector_photo_url` и список `partnership_matches`. Совпадение
содержит название продукта, предложение, основание, вопрос для встречи,
HTTPS-ссылку на запись каталога и `basis_fact_ids`; API принимает только ссылки
на выбранные принятые факты. Без результата матчинга выводится явная отметка,
а не выдуманные продукты или рекомендации. GET предпросмотра — одноимённый query-параметр. Вариант сохраняется с материалом
и заданием, входит в проверку повторного ключа запроса и показывается в списке
отчётов. Выбор оформления не меняет запрос извлечения, снимок фактов или проверку.

## Подробная справка

Основной шаблон Демо 1 — `customer-card.json`, версия `customer-card-v1`.
Оформление и структура основаны на примерах ИКЭСТ/ИРНИТУ заказчика с улучшениями:
читаемый текст, отдельные источники, отсутствие пустых неподтверждённых показателей.
Это рабочая адаптация примеров, не заявление о согласованном корпоративном стандарте.

Секции задаются списком `sections`: `overview`, `head`, `biography`, `institution`,
`leadership`, `questions`, `theses`, `sources`. Их можно переставлять/отключать.
Сначала идут первый руководитель и биография, затем справка об учреждении и остальные
сотрудники. `head` показывает образование, степень, звание, назначение и контакты;
карьерные этапы упорядочены по годам. Неизвестные разделы перечисляются как
«Не подтверждено в выбранных материалах», без нулей и выдуманных значений.
Численность выводится вместе с `metric_context.period/scope/unit`; показатели
разных форм обучения, лет и филиалов не складываются автоматически.
Фото руководителя пока не загружается; чужие портреты из примеров не используются.

Предпросмотр кандидатов создаётся через `dossier_preview.py` отдельно от обычных
материалов. Все его слайды имеют явную пометку «КАНДИДАТЫ НЕ ПРИНЯТЫ»; проверка
сотрудника не имитируется. PDF-источники объединяются по хешу исходного файла,
при этом в заметках сохраняются страницы и хеши каждого извлечённого текста.
Карьерные этапы переносятся между слайдами целиком, если помещаются; отсутствующие
сведения о руководителе выводятся примечанием и не создают пустой слайд.

Контрольный макет с вымышленными данными: из `backend` выполнить
`python -m examples.llm.dossier_demo`. Он создаёт отдельную БД и PPTX в
`output/dossier-fixture`; это проверка вёрстки, не реальные данные заказчика.
Пустые разделы пропускаются; длинный текст переносится на дополнительные слайды,
без молчаливого обрезания. Точное наполнение можно изменить после согласования структуры.

Логотипы учреждений, численность и показатели из примеров не копируются. Они не
становятся данными другого вуза. Основной шаблон заполняется
снимком принятых фактов, сохранённым вместе с материалом; модель не переписывает
должности, контакты и биографические значения при вёрстке. Вопросы/контекстные тезисы
берутся из черновика LLM со ссылками. Результат остаётся черновиком до проверки текста.

`assets/sber-logo.png` и два градиента извлечены без изменения из макетов
`Карточка_ИКЭСТ_2025.pptx`, предоставленного заказчиком. Логотип сохраняет пропорции.
Данные, фотографии и логотипы ИКЭСТ из слайдов не используются. `sber-gradient-cover.jpg`
сохранён для возможного отдельного титульного слайда; основной шаблон использует
только `sber-gradient-header.jpg`.

`meeting.json` / `meeting-v1` — первоначальный универсальный текстовый вариант;
остаётся резервом для старых вызовов генератора, не передающих структурированные факты.
HTTP-сценарий Демо 1 использует `customer-card-v1` и неизменяемый снимок выбранных фактов.

Название подразделения отображается рядом с сотрудником. На обзорный слайд как
руководитель учреждения попадает только явно принятый ректор/директор без области
подразделения; директор филиала и первый произвольный сотрудник не подставляются
вместо руководителя головного учреждения.
