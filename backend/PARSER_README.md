# Парсер «Карточка ВУЗа»

Модуль сбора и очистки данных с официальных сайтов вузов и агрегаторов
(Вузопедия / Поступи.Онлайн). Готовит:

1. `UniversityData` — структурированную карточку вуза, включая паспорт из
   агрегатора, ректорат с фото и публикации о сотрудничестве со Сбером.
2. `SourceDocument` — очищенные документы с фрагментами и контактными
   подсказками, совместимые с LLM-контрактами `app.services.llm`.

## Запуск

Дополнение Демо 1: официальные текстовые PDF можно передать через `pdf_sources`
серверного сценария. Номера выбранных страниц и хеш файла сохраняются вместе с
цитатами; PDF/сканы не превращаются в HTML. Подробнее —
[`DOSSIER_PIPELINE.md`](docs/llm/DOSSIER_PIPELINE.md#pdf-и-предпросмотр).

Из каталога `backend/`:

```bash
python -m parser.main --profile hse
python -m parser.main --profile urfu
python -m parser.main --all
```

Парсер всегда использует вместе **официальный сайт и агрегаторы** (отдельного
режима «только агрегаторы» больше нет). С официального сайта берутся разделы
из настройки `sections` (по умолчанию: основные сведения, руководство,
контакты, специальности, наука, проекты, партнёрство, новости). Паспорт вуза
(город, статус, факультеты, специальности) — из Вузопедии и Поступи.Онлайн.
Баллы ЕГЭ и число мест не собираются.

```bash
python -m parser.main --name "Уральский федеральный университет"
python -m parser.main --profile hse --sections about,leadership,contacts,programs
python -m parser.main --profile hse --full-site   # плюс гранты, мероприятия, достижения
```

## Что попадает в карточку

Карточка готовит материал к встрече с вузом, и всё в ней проверяется вручную,
поэтому парсер оставляет только нужное:

- **Основное руководство** — ректор, президент, первый проректор, проректоры,
  научный руководитель (до 20 человек, `PARSER_MAX_LEADERSHIP`). Директора
  центров, деканы и заведующие в карточку не попадают. Если в «Структуре и
  органах управления» проректоров нет, парсер находит страницу «Ректорат» /
  «Руководство» и берёт их оттуда вместе с личными телефонами и почтой.
- **Контакты** — общие контакты вуза, приёмная ректора и контакты основного
  руководства (до 40). Контакты подразделений и приёмной комиссии отбрасываются.
- **Специальности** (`specialties`) — код, название, уровень (бакалавриат,
  магистратура…) и укрупнённая группа (УГСН). Источник — раздел
  «Образование» официального сайта (`/sveden/education/`, микроразметка
  `eduCode`/`eduName`), при его отсутствии — страницы программ агрегаторов.
- **Направления сотрудничества со Сбером** (`cooperation_directions`) — ИИ и
  данные, кибербезопасность, финансы, право, медицина, EdTech, связь, маркетинг,
  HR. Для каждого направления указаны основания: число и примеры программ,
  научные подразделения и новости о сотрудничестве. Направления с уже
  найденным сотрудничеством идут первыми. Это подсказка для подготовки, её
  нужно проверить.
- **Новости о сотрудничестве со Сбером** (`news_mentions`) за последние 24 месяца.

Из корня репозитория:

```bash
python -m backend.parser.main --profile hse
```

Произвольный сайт или список:

```bash
python -m parser.main --url https://example.ru --name "Пример"
python -m parser.main --input-file universities.txt
```

Форматы `--input-file`: URL, `Название, URL`, CSV/TSV или JSON-список
`{"name": "...", "url": "..."}`.

## Создание карточки по названию (без ссылки)

Парсеру можно не передавать URL вообще:

```bash
python -m parser.main --name "Национальный исследовательский университет «Высшая школа экономики»"
```

Он сам находит официальный сайт (Википедия/Wikidata, затем поиск Bing/DuckDuckGo
с проверкой главной страницы), руководство, страницу ректора и фото.
Найденный сайт принимается, только если его название совпадает с запросом:
совпадения по общим словам («университет», «федеральный») недостаточно.
Короткие названия («УрФУ», «СПбГУ», «НИУ ВШЭ») сверяются с аббревиатурой.

Если передан только `--url`, название берётся с главной страницы сайта
(`og:site_name`/`<title>`). Без названия агрегаторы и поиск новостей не
запускаются: иначе нельзя проверить, что найден нужный вуз.

В активном API интерфейса добавлен единый маршрут первичного сбора:

```text
POST /api/v1/ai/cards/intake
{"name": "НИУ ВШЭ", "city": "Москва", "request_key": "..."}
→ 202 + card + job (сервер находит сайт и запускает парсер и извлечение фактов)
```

Поле `website` можно передать, если официальный адрес уже известен. Без него backend вызывает тот же автоопределитель, что и парсер, затем сохраняет карточку и ставит фоновое задание в SQLite-хранилище `DemoRepository`. Статус и результаты доступны через `/api/v1/ai/cards/{card_id}` и `/api/v1/ai/jobs/{job_id}`.

В API сбор идёт только по публичной сети: это касается и резервной загрузки
через `curl_cffi`/Playwright (адреса, разрешающиеся во внутренние IP,
блокируются и в браузере). Агрегаторы и поиск новостей в сборщике документов
для LLM отключены: они не входят в документы и только замедляли обновление.

## Профили

`spbu`, `hse`, `rsuh`, `urfu`, `msu`. Профиль задаёт проверенные URL разделов;
для остальных сайтов разделы ищутся автоматически по меню, ссылкам,
`sitemap.xml` и ключевым словам.

## Агрегаторы, фото ректора и новости о Сбере

- `curl_cffi` с TLS-отпечатком Chrome; при 403/Cloudflare и флаге
  `--playwright` подключается браузерный stealth-рендеринг.
- Вузопедия и Поступи.Онлайн дают паспорт: город, статус, общежитие, военную
  кафедру, факультеты и специальности. Если поиск Вузопедии закрыт проверкой
  «вы не бот», карточка вуза ищется через обычный поисковик; саму проверку
  проходит только браузер (`--playwright` и `python -m playwright install chromium`).
- Для ректора извлекается прямая ссылка на фото (`img`, CSS `background-image`,
  `og:image`), статус (ректор / и.о.), телефон и email приёмной.
- Новости о сотрудничестве со Сбером ищутся по запросам
  `"<вуз>" Сбербанк сотрудничество` и `"<вуз>" Сбербанк`.
  Порядок поисковиков: **Яндекс → Google → Bing News → Bing → DuckDuckGo**
  (для поиска сайта и карточек агрегаторов — Яндекс → Google → Bing →
  DuckDuckGo). Рекомендуемая схема — **Yandex Search API** (Yandex Cloud):
  задайте `YANDEX_SEARCH_FOLDER_ID` и `YANDEX_SEARCH_API_KEY`. Это официальный
  способ получать выдачу Яндекса — лучший по качеству для русскоязычных вузов
  и новостей и без капчи. Используется API v2
  (`searchapi.api.cloud.yandex.net/v2/web/search`), при ошибке — v1 (XML); с
  ключами Яндекс опрашивается только через API. Аналогично для Google —
  `GOOGLE_CSE_KEY` и `GOOGLE_CSE_ID` (Programmable Search). Без ключей парсер
  пробует обычную выдачу Яндекса и Google, но они почти всегда отвечают
  капчей; поисковик, ответивший капчей, пропускается 30 минут, и поиск уходит
  в запасные Bing и DuckDuckGo, результаты которых нестабильны. Публикация засчитывается, только если в ней упомянут именно этот вуз
  (сокращение или отличительные слова названия) и есть признак сотрудничества
  (соглашение, лаборатория, кафедра, стажировки и т. п.). Поиск идёт и по
  «Сбербанк», и по «Сбер».
  Публикации старше `--news-months` (по умолчанию 24) отбрасываются, остальные
  сортируются от новых к старым.
- При полном обходе новости официального сайта, где упомянут Сбер, тоже
  попадают в `news_mentions` (источник `official_site`) и идут первыми.
- Запросы к агрегаторам и поисковикам идут с паузой между обращениями к одному
  хосту. Chromium один на задание и не больше `PARSER_MAX_BROWSERS` (по
  умолчанию 1) на весь сервер; картинки, видео и шрифты в нём не загружаются.

> Важно: Вузопедия и Поступи.Онлайн не содержат блока «Руководство» и фото
> ректора. Парсер сам находит официальный сайт и страницу ректора через
> поисковик и типовые адреса (`/rector/`, `/about/rector/`), без ручных ссылок.
> Отключить автопоиск: `--no-rector-lookup`.

```bash
python -m parser.main --profile hse --aggregator auto --max-news 5
python -m parser.main --profile hse --aggregator-url https://msu... --playwright
python -m parser.main --profile hse --no-aggregators --no-news-search
```

## Результаты

По умолчанию:

```text
data/output/<slug>/<slug>_card.json
data/output/<slug>/<slug>_documents_<timestamp>.json
data/output/<slug>/<slug>_llm_card_<timestamp>.json
data/output/<slug>/<slug>_changes_<timestamp>.json
data/parser.sqlite3
data/cache/pages.json
data/logs/parser.log
```

`data/` исключён из git: результаты парсинга не коммитятся. HTML кэша хранится
отдельными файлами в `data/cache/pages_pages/`, а `pages.json` — только индекс.
Запуск, который не получил ни руководства, ни документов, ни паспорта
(например, из-за сбоя сети), не перезаписывает последний `*_card.json`.

`*_llm_card_*.json` — полный нативный `UniversityData`, включая документы и фрагменты,
для [LLMWorkflow / workflow_cli](docs/llm/LLM_WORKFLOW.md). Старый `*_card.json`
не содержит документов; описательный `*_documents_*.json` не является этим входным контрактом.
В серверном сценарии Демо 1 `UniversityParser.parse(..., allowed_sections=...)`
ограничивает сбор руководством/контактами. При проблемах автообнаружения UI позволяет
передать точную страницу руководства на том же официальном домене.

## Категории документов

`organization`, `leadership`, `contacts`, `research`, `projects`, `grants`,
`project_news`, `partnerships`, `achievements`, `other`.

Документ в файле `*_documents_*.json` имеет вид:

```json
{
  "university": {"name": "...", "official_domain": "university.ru"},
  "document": {
    "category": "project_news",
    "title": "...",
    "url": "...",
    "published_at": "2026-11-03",
    "collected_at": "2026-11-03T15:00:00Z",
    "language": "ru",
    "content": "...",
    "content_hash": "sha256...",
    "content_type": "text/html",
    "fragments": []
  }
}
```

## Интеграция с LLM-модулем

Адаптер: `parser/llm_adapter.py`. Он не импортирует `app`, поэтому может
использоваться и в API, и в отдельных скриптах.

```python
from parser.llm_adapter import to_llm_request, to_officials

card = parser.parse(profile="hse")

# Schema 0.2: руководство и контакты с фрагментами.
request = to_llm_request(card, institution_id="hse", card_version=1)

# Schema 0.3: профиль, проекты и события.
context_request = to_llm_request(
    card, institution_id="hse", schema_version="0.3"
)

# Представление руководителей для API
officials = to_officials(card, institution_id="hse")
```

Полученный `request` валидируется контрактами
`app.services.llm.fragment_models.FragmentExtractionRequest` (0.2) или
`app.services.llm.context_models.ContextExtractionRequest` (0.3).

Контакт без подтверждённого структурой страницы или заголовком владельца остаётся в тексте, но не
превращается в структурированную подсказку с выдуманным владельцем.
Карточки с microdata `rucovodstvo` / `rucovodstvoZam` сохраняются отдельными
фрагментами; `fio` задаёт владельца рабочих контактов. В `rucovodstvoFil`
владельцем контакта считается филиал `nameFil`, а не директор. Вложенные карточки
разделяются. Обозначенные внутри личной карточки контакты приёмной/секретаря не
переносятся на человека. Добавочный номер до четырёх цифр сохраняется дословно,
если общий номер удовлетворяет ограничению контракта 0.2 (до 15 цифр).
Общие заголовки «Руководство» и «Руководитель и заместители» не задают владельца.
В простых microdata-таблицах с заголовком ФИО и без колонок подразделений контакты
привязываются к человеку. Справочники с явными колонками подразделения и email
читаются отдельно, включая однозначные `rowspan`; почта принадлежит подразделению.
Колонки положений/подписей документов не включаются в текст такого справочника,
чтобы ФИО подписанта не становилось текущим назначением. Общий телефон справочной
службы не приписывается подразделению по соседству. Сложные `colspan`, неверная
сетка и неоднозначная область остаются без автоматической разметки владельца.
`subject_department` передаёт дословное название филиала/подразделения в 0.2-контракт;
оно должно присутствовать в том же фрагменте. Неизвестный владелец не угадывается.
При чтении HTML из кэша `retrieved_at` сохраняет дату загрузки страницы;
повторная очистка не подтверждает актуальность сайта. В `metadata.cache_status`
отмечается использование сохранённой или устаревшей копии.

В режиме 0.3 весь документ не считается одной областью сущности. По умолчанию
фрагменты независимы: это предотвращает перенос статуса между разными проектами
на странице списка. Если парсер надёжно выделил одну статью/проект, его фрагментам
можно явно задать одинаковый `DocumentFragment.entity_scope_id`. Без такой
разметки связи между разными абзацами потребуют дополнительной обработки.
