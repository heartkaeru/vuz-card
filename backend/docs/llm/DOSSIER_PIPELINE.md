# Досье руководителя и справка об учреждении

Расширение Демо 1, 4 ноября 2026. Структура рабочая, её можно уточнить с заказчиком.

## Сценарий

В карточке открыть «Источники руководства, биографии и справки об учреждении».
Можно указать страницу руководства, официальную биографию первого руководителя и
до трёх справочных HTML-страниц и PDF-отчёт с выбором страниц. Все дополнительные адреса проверяются относительно
официального домена карточки; допустимы его поддомены. Ключ GigaChat остаётся на сервере.
Флажок справки включает извлечение `0.3` вместе с руководством `0.2` в одном исследовании.
Без него API по умолчанию сохраняет прежний сценарий `0.2`.

Новые поля биографии: `person.academic_title`, `person.interests`, `appointment.since`.
Образование, степень, карьера и ответственность используют прежние поля. Историческое
исполнение обязанностей и избрание не означают текущее назначение.

`biography_subject` — связь исходного абзаца с именным заголовком страницы.
Парсер разделяет длинные абзацы на предложения с исходными Unicode-смещениями.
LLM может выбрать `value_fragment_id`; сервис переносит предложение без перепечатки.
Указание одновременно `value` и `value_fragment_id` запрещено. Ссылка на заголовок
сохраняется в доказательствах даже при обработке разных пакетов текста.
Эта привязка не заменяет подтверждение текущей должности или владельца контакта.
Перечень публикаций без явной формулировки научных интересов не принимается в это поле.

Поля справки: `institution.profile`, `type`, `location`, `founded`, `education_areas`,
`education_levels`, `students`, `structure`. Для выделенной справочной страницы
`institution_anchor_id` связывает абзацы с фрагментом, в котором назван вуз.
Якорь повторяется в пакетах LLM, но исходный документ и цитаты не изменяются.
Эту связь нельзя использовать для проектов/событий. Допустим выбор `value_fragment_id`.
Отдельный год из истории не подтверждает основание учреждения; нужна исходная
формулировка о создании. Проверяющий должен отличить её от создания филиала.

## Численность

`institution.students` требует `metric_context` с дословными значениями:

- `period`: дата, учебный или отчётный год;
- `scope`: контингент, форма/уровень обучения, головной вуз или филиалы;
- `unit`: единица измерения, например «человек».

Необязательное `coverage` отдельно хранит дословный охват: например, «включая филиалы».
Это позволяет не склеивать разные части исходного предложения в выдуманную цитату.
В `0.3` можно вернуть одновременно `value` и `value_fragment_id`: сервис проверит,
что значение дословно присутствует именно в выбранном фрагменте. Для биографии `0.2`
по-прежнему выбирается одно представление значения.

Квалификаторы должны присутствовать в доказательствах того же источника и области.
Дата скачивания не заменяет период показателя. Нет периода/состава — кандидат
отклоняется, значение нельзя принять или экспортировать. Суммы и доли не вычисляются.
Лексическая проверка не доказывает правильное соответствие строки и числа в сложной
таблице: сотрудник проверяет эту связь, текущую структуру и классификацию биографии.

## PDF и предпросмотр

API обновления принимает `pdf_sources: [{url, pages}]`. Нумерация PDF начинается с 1;
до 20 страниц на источник, до двух источников. Без списка используются первые 20
страниц. Лимит документа — 300 страниц, размер ограничен настройкой загрузчика
(по умолчанию 5 МБ). Извлечение текстовое; сканы и защищённые PDF дают явную ошибку.
HTTP-загрузка ограничивается по мере чтения потока, сертификаты проверяются.

Сохраняются точный извлечённый текст, Unicode-смещения, номер страницы, SHA256 текста
и отдельный SHA256 исходного PDF. Год из имени файла и дата скачивания не становятся
периодом численности. Именной титул с «за … год» может дать область учреждения и
период отчёта. В сложных/повёрнутых таблицах порядок текста приблизителен: нужна
проверка исходной страницы. В интерфейсе ссылка цитаты открывает нужную страницу.
Выбранные PDF-страницы имеют приоритет перед автоматически найденными общими страницами.

`GET /runs/{run_id}/preview?expected_revision=N` создаёт отдельный PPTX по прошедшим
проверку кандидатам и ранее принятым фактам. На каждом слайде указано, что кандидаты
не приняты. Предпросмотр не записывает решения проверки, не создаёт принятый материал
и не разблокирует генерацию по непринятым данным. Проверяется актуальность ревизии.
В API нет скрытого автопринятия. Уточнённые по источнику кандидаты маркируются
`origin=curated_candidate`; это также не решение сотрудника.

## Проверка и результат

Все прошедшие автоматические проверки факты получают `pending`. Решение сотрудника
с датой, именем и основанием обязательно. История ранее принятых фактов не переписывается;
новый сбор создаёт новое исследование и делает предыдущие материалы устаревшими.

Повторное исследование сохраняет неизменяемый снимок ранее принятых фактов
(`baseline_facts`, `previous_run_id`). Активная карточка вычисляется как принятые
сведения этого снимка и нового исследования за вычетом явно архивированных ID.
Одинаковые принятые значения используют новое доказательство только после проверки;
дата проверки старого значения автоматически не обновляется.

`GET /runs/{id}/changes` возвращает категории `new`, `changed`, `head_change`,
`unchanged`, `not_confirmed`, обе стороны сравнения и `approved_facts`.
Сопоставляются ФИО/владелец, подразделение и поле; численность — также период,
состав, охват и единица. Биографические выдержки могут дополнять друг друга,
поэтому новая выдержка не считается автоматической заменой старой.
Проекты/события не объединяются только по похожему названию.

При `accept` заменяющего кандидата `POST /runs/{id}/reviews` требует точный
список `retirements: [{fact_id, source_checked: true, reason}]` из сравнения.
Изменения и архивирование записываются одной транзакцией с проверкой ревизии;
неизменяемый аудит содержит автора, основание, время и прежний факт.
При смене руководителя архивируется подтверждённый профиль прежнего человека:
он не переносится новому. Неоднозначный выбор руководителя блокируется.
Архивирование не меняет старый статус проверки в историческом исследовании.

Отсутствие кандидата и сбой сбора не архивируют факты. Даже при статусе `failed`
можно формировать материалы по сохранившимся активным принятым сведениям,
если действующие проверки давности пройдены; добавляется предупреждение о сбое.
Снимок фактов в материале также включает факты из предыдущего исследования.
`GET /cards/{id}/history` возвращает последние 20 исследований; прежние версии
доступны для чтения, а проверка и экспорт по вытесненному исследованию запрещены.

PPTX собирается из точных снимков принятых фактов: обзор встречи, руководитель,
карьера, справка об учреждении, остальные сотрудники, вопросы/проекты при наличии,
источники. Длинный текст разбивается на слайды. В заметках сохраняются ID, URL,
дата получения, хеш и смещения. Неподтверждённые критерии обозначаются явно.

Ограничения: нет загрузки портрета, распознавания сканов/OCR, автоматического мониторинга
изменений и гарантии полноты. Страница истории может содержать устаревшие сведения;
её факты нельзя автоматически считать текущими. Текст справки остаётся черновиком.
