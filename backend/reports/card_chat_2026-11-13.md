# Диалог по карточке вуза

Проверка от 13.11.2026, ветка `codex/education-partnership-matching` от `998af9a`.

Откройте сохранённую карточку, нажмите кнопку ИИ-агента и войдите под учётной записью ВУЗ-CRM. При первом запуске можно зарегистрироваться в панели чата. Локальному серверу нужен `JWT_SECRET_KEY` в `backend/.env`. См. [настройку авторизации](../docs/AUTH.md).

История хранится в SQLite по пользователю и ID карточки. Интерфейс показывает последние 20 обменов. В контекст GigaChat поступают до шести последних обменов по текущей ревизии. После актуализации или принятия новых фактов прежние сообщения остаются видимыми, а модель отвечает по текущей версии карточки.

Для вопросов о карточке модель вызывает `read_card` с разделом и, при необходимости, именем человека. Сервер проверяет аргументы, подставляет данные выбранной карточки из принятых фактов и формирует ссылки на источники по ID из ответа. Если ни одного факта ещё не принято, сервер сообщает об этом сразу. Кнопки актуализации и презентации вызывают существующие операции карточки.

- **Живой прогон.** GigaChat прочитал сведения о руководстве БГУ. На вопрос «А как с ним связаться?» модель передала в `read_card` ФИО из предыдущего ответа и вернула телефон и почту с двумя ссылками на факты. Использована локальная ревизия 2 с 20 ранее принятыми фактами, описанная в [отчёте от 5 ноября](presentation_variants_2026-11-05.md). Прогон сделан на сохранённых данных в режиме чтения. [Официальный источник БГУ](https://bgu.ru/sveden/managers/default.aspx)
- **Проверки кода.** Сквозной API-тест проверяет сохранение диалога, изоляцию по пользователю и вузу, исключение кандидатов и отклонение неизвестных ссылок на факты. Для него используется подставной провайдер.

## Точечные правки

В чате можно попросить заменить одно существующее принятое значение. Поддерживаются рабочая почта и телефон, должность, профиль и направления подготовки, описания проектов и событий. При нескольких совпадениях нужно указать владельца и прежнее значение. Агент показывает поле, владельца, прежнее и новое значения. Для записи нажмите «Подтвердить правку».

Подтвердить предложение может автор запроса. Сервер повторно проверяет ревизию и сохраняет замену вместе с автором, временем и обоими значениями в журнале решений. Новое значение помечается как подтверждённое сотрудником и сохраняется при повторном сборе по правилам принятой карточки. Источник прежнего значения остаётся в истории.

- **Живой предпросмотр БГУ.** GigaChat вызвал `propose_card_edit` для рабочей почты ректора и вернул предпросмотр замены на учебный адрес. Использована сохранённая ревизия 2 с 20 принятыми фактами. База открыта в режиме чтения. [Источник прежнего контакта](https://bgu.ru/sveden/managers/default.aspx)
- **Проверки кода.** Тест API на учебных данных проверяет, что предпросмотр не меняет карточку, подтверждение требует JWT автора запроса, устаревшая правка отклоняется, а новое и прежнее значения фиксируются в журнале.

## Создание карточки и первичный сбор — 14.11.2026

В чате можно написать «Создай карточку и собери сведения. Название: Байкальский государственный университет. Официальный сайт: https://bgu.ru». Город можно указать в том же сообщении. После вызова `collect_card` открывается карточка, где отображается состояние фонового задания. Найденные сведения поступают на проверку сотруднику.

Сервер сверяет URL с сообщением и использует существующую карточку при однозначном совпадении сайта. Повтор с тем же ключом возвращает прежнее задание. Пока сбор выполняется, новый запрос для того же сайта возвращает текущее задание. Парсер для этого сценария проверяет адрес назначения при подключении, включая переадресации и запрос `robots.txt`.

Проверки API с подставным провайдером и парсером покрывают создание черновика, запуск фоновой задачи, повтор запроса, кандидатов до принятия и отказ при подмене URL. Отдельные тесты проверяют отказ для непубличных DNS-адресов и переадресаций.

Живой прогон во временной базе. GigaChat вызвал `collect_card` по названию и официальному URL БГУ. Парсер получил три документа. Задание завершилось частично с 33 записями о фактах и нулём подтверждений сотрудником. При извлечении сработали ограничения `fragment_too_large` и `context_batch_limit_reached`.

### Ответ на вопрос о руководителе — 14.11.2026

На прямой вопрос «Кто руководит вузом» сервер отвечает по действующей принятой должности и прикладывает источник. При отсутствии принятой записи чат направляет сотрудника к проверке руководства. Ответ сохраняется в контексте для уточняющего вопроса. На сохранённых карточках БГУ и НИЯУ МИФИ проверен выбор ректора со ссылкой на источник. Проверка читала локальную базу и не вызывала GigaChat. Тест API покрывает ответ до и после принятия фактов, а также передачу ответа в контекст уточняющего вопроса.
