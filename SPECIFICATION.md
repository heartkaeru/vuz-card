# ВУЗ-CRM: варианты платформы и общая схема

## Варианты платформы

| Вариант | Сильные стороны | Ограничения |
|---|---|---|
| Odoo Community | Готовая CRM и возможность доработок | Внешний API Odoo 19 по документации доступен на тарифе Custom; редакцию и размещение нужно проверить |
| SuiteCRM | Готовая CRM, REST API, права доступа и фоновые задания | Для настройки и сопровождения нужны специалисты по PHP/Symfony |
| EspoCRM | Готовая CRM, API, настраиваемые карточки и права на поля | Для сложных длительных операций потребуется отдельный обработчик |
| FastAPI | Полный контроль над карточками и интеграциями | Интерфейс, права, администрирование и CRM-функции команда создаёт сама |

**Предварительный вывод:** сравнить SuiteCRM и EspoCRM с FastAPI на одном прототипе. Odoo включить, если у заказчика уже есть эта система или нужны её дополнительные бизнес-модули. До выбора проверить API, стоимость и лицензионные условия.

## Общая схема

**Пользователь → интерфейс → сервер ВУЗ-CRM → база данных.** Сервер проверяет права, читает и меняет карточки и создаёт задания. Долгие задания идут через очередь к обработчику. Обработчик связывается с парсером и нейросетью, а файлы сохраняет в отдельном хранилище.

Интерфейс, парсер и нейросеть не имеют прямого доступа к базе CRM. Запросы к карточкам и файлам проходят через сервер, который проверяет права пользователя.

## Поток актуализации

1. Пользователь открывает карточку; сервер возвращает только доступные ему данные.
2. Пользователь запускает актуализацию; сервер создаёт задание и возвращает его номер.
3. Обработчик получает материалы через парсер, передаёт их нейросети и сохраняет результат.
4. Сотрудник проверяет результат. После подтверждения сервер обновляет карточку и журнал изменений.
5. Для презентации обработчик использует разрешённые данные карточки, создаёт файл и сохраняет его для скачивания.

Правила сбора материалов и анализа нейросетью описываются отдельно.

## Запросы к серверу

Обмен идёт по HTTPS в формате JSON. Пользователь входит в систему; сервер проверяет его права на каждую операцию. Таблица описывает назначение запросов и состав данных, без программных примеров.

| Операция | Адрес и метод | Что передаётся | Что возвращается |
|---|---|---|---|
| Получить карточку | `GET /api/v1/universities/{id}` | Идентификатор ВУЗа | Название, сайт, профиль, версия и дата изменения |
| Изменить карточку | `PATCH /api/v1/universities/{id}` | Версия карточки и изменяемые поля | Обновлённая карточка и новая версия; при устаревшей версии — конфликт |
| Запустить актуализацию | `POST /api/v1/universities/{id}/refresh` | Версия карточки и ключ защиты от повторного запроса | Номер задания и начальный статус |
| Проверить задание | `GET /api/v1/jobs/{job_id}` | Номер задания | Тип, состояние, прогресс, результат или код ошибки |
| Сформировать презентацию | `POST /api/v1/universities/{id}/presentations` | Шаблон, формат, версия карточки | Номер задания |
| Скачать презентацию | `GET /api/v1/presentations/{id}/download` | Идентификатор презентации | Файл или временная ссылка после проверки прав |

Состояния задания: ожидает, выполняется, повторяется, завершено успешно, завершено с ошибкой или отменено. Если карточка успела измениться, сервер не перезаписывает новые данные старой версией.

## Очередь долгих заданий

1. Сервер сохраняет задание и отметку о его отправке в очередь.
2. Очередь передаёт обработчику номер и тип задания; содержимое карточки и исходные тексты в сообщение не включаются.
3. Обработчик выполняет задачу и сохраняет результат в базе или файловом хранилище.
4. После сохранения результата задача отмечается завершённой. Повторная доставка задания не должна повторно применять результат.
5. При временной ошибке выполняются до трёх повторов. Если они не помогли, задание помечается ошибочным для разбора.

База хранит окончательный статус. Конкретную технологию очереди и интервалы повторов определить при прототипе.

## Права доступа

| Роль | Просмотр | Изменение карточки | Запуск задач | Подтверждение результата ИИ | Управление ролями |
|---|---:|---:|---:|---:|---:|
| Просмотр | Да | Нет | Нет | Нет | Нет |
| Редактор | Да | Да | Да | По разрешению | Нет |
| Руководитель | Да | Да | Да | Да | Нет |
| Администратор | Да | Да | Да | Да | Да |
| Сервисная учётная запись | Только нужные данные | Только необходимые действия | Назначенные задачи | Нет | Нет |

Доступ ограничивается назначенными ВУЗами и отдельными полями. Скачивание файлов тоже требует проверки прав. Ключи интеграций хранятся на сервере, не в браузере.
